design MCP 사용법

Claude 에게 우리 팀 디자인 규칙(색 · 글자 · 컴포넌트 · 문구)과 화면 진행 상황을 물어볼 수 있게 해 주는 도구예요. 읽기 전용이라 누가 써도 자료가 바뀌지 않아요.

📊 디자인 진행 현황은 디자인 현황판에서 한눈에 볼 수 있어요.
👀 이 페이지가 보인다면 정상이에요. 이 주소는 웹사이트가 아니라 Claude 에 등록해서 쓰는 주소예요. 아래 방법으로 Claude 에 한 번만 등록하면 돼요.

1. 설치 — 한 번만 하면 돼요

Claude Code (터미널) 를 쓰는 경우

아무 폴더에서나 아래 한 줄을 붙여 넣으세요. Python 같은 설치는 필요 없어요.

claude mcp add --transport http --scope user design __URL__

그다음 Claude Code 안에서 /mcp 를 입력해 design · connected 가 보이면 끝이에요.

claude.ai (웹 · 데스크톱 앱) 를 쓰는 경우

설정의 커넥터 메뉴에서 사용자 지정 커넥터 추가를 누르고, 이름은 design, 주소는 아래를 붙여 넣으세요.

__URL__

대화창의 도구 목록에서 design 이 켜져 있는지 확인하세요.

2. 이렇게 물어보세요

도구 이름을 몰라도 돼요. 평소 말로 물어보면 Claude 가 알아서 골라 써요.

알고 싶은 것이렇게 물어보기
색 · 글자 · 간격 값「경고 색 토큰 알려 줘」 「요약 카드 배경색은?」
컴포넌트 · 문구 규칙「버튼은 언제 써?」 「반납 지연은 어떻게 보여 줘?」 「오류 문구 규칙」
글자가 잘 보이는지「positive.primary 글자를 요약 카드 배경에 써도 돼?」
화면 진행 상황「수정 필요한 화면은?」 「개발에 넘어온 화면은?」
전체 진행률「디자인 몇 % 됐어?」 「주간 보고용 디자인 현황 정리해 줘」

3. 역할별로 이렇게 써요

누가예시
디자이너「수정 필요한 화면과 이유, 관련 토큰 대비를 보여 줘」
개발자「개발에 넘어온 화면과 각 화면의 컴포넌트 규칙을 정리해 줘」
PO · 기획「디자인 진행률을 주간 보고 형식으로 정리해 줘」
리뷰어「이 화면 코드에 토큰에 없는 색이나 대비 부족이 있는지 봐 줘」

4. 들어 있는 도구 5개

도구하는 일
find_tokens디자인 토큰(색 · 글자 · 간격 · 모서리 · 선) 찾기
read_guide컴포넌트 · 상태 표현 · 문구 규칙 문서 보기
check_contrast글자색 · 배경색 대비를 WCAG 기준으로 검사
list_screens화면별 디자인 상태 · 개발 넘김 여부 보기
design_progress전체 디자인 진행률 계산

5. 자주 묻는 질문

/mcp 에서 design 이 failed 로 나와요

주소를 정확히 붙여 넣었는지 확인하고(끝이 /mcp), Claude Code 를 껐다 켜 보세요. 회사 · 학교 네트워크가 외부 주소를 막는 경우도 있어요.

자료는 어디서 바꾸나요?

GitHub 레포 mugee1/mcp-practice 의 design-mcp/ 폴더(design_tokens.csv · screens.csv · docs/)를 고쳐 main 에 올리면 몇 분 안에 모두에게 반영돼요. 도구로는 바꿀 수 없어요.

답에 자료에 없는 내용이 나오면?

이 도구는 자료에 없는 건 「없다」고 답하게 되어 있어요. 그래도 이상한 답이 나오면 디자인 담당에게 알려 주세요.

아무나 이 주소를 써도 되나요?

지금은 공개 · 읽기 전용이에요. 연습용 자료만 들어 있어요. 공개하면 안 되는 자료를 넣게 되면 접속 키를 켤 예정이에요.
